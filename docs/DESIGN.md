# 设计

## 0.2.2 标签分层

- 第一层固定显示母标签：全部、团建游戏、团建转化、合集攻略。
- 第二层使用两个紧凑的可展开组：季节、节日；子标签附带真实数量，零结果不显示。
- 地区不是独立筛选维度，避免右侧窄栏被大量地点按钮占满。
- 不同维度可以叠加，形成“团建转化 + 夏季 + 端午节”一类交集筛选。

## 0.2.1 数据可信度

- 筛选必须覆盖全素材库，而不是只筛选当前展开分类。
- 使用次数以成功生产事件为证据；素材链接记录、制作日志和扩展实时发送记录合并去重。
- 旧路径变化后只允许“唯一同名”自动关联，多候选或无候选都进入待核对，不猜测。
- 全库索引后台逐分类生成，页面最多同时渲染 240 条筛选结果，避免大库拖慢 ChatGPT。

## 0.2.0 素材身份与母标签

- 每个素材文件夹只有一个母标签，取值限定为“团建游戏 / 团建转化 / 合集攻略”。
- “聚会游戏、破冰游戏、团队游戏”等只是同一业务类型的不同叫法，统一映射到母标签“团建游戏”，不在界面重复堆叠。
- 人工标签优先于自动识别；文件夹身份由独有目录哈希绑定，因此同卷改名或移动不丢失标签和次数。
- 标签、次数和搜索属于筛选维度，不改变素材目录结构；真实移动仍需二次确认。
- 文件夹快捷按钮允许配置显示、名称和固定移动目录，设置入口保持轻量，不另建大型后台。

## 0.1.9 原生优先

- ChatGPT 左侧会话属于网站原生界面，扩展不搬动节点、不代理会话点击。
- 素材拖放只在中间聊天区解释为上传；拖到右侧文件树目标时解释为文件夹移动，两种动作都有明确反馈。
- 已有草稿属于用户内容，扩展只能追加生产指令，不得清空或覆盖。
- 真实文件移动属于有风险操作，必须先展示来源和目标并确认；本地端负责最终安全校验。

## 0.1.8 防重边界

- 路径用于快速命中，内容指纹用于抵抗改名和移动。
- 内容指纹由帖子文件夹内图片、TXT、Markdown 的 SHA-256 聚合生成，不依赖文件名。

## 0.1.7 素材状态

- “已加入 GPT”只表示附件和指令进入当前草稿，不等于已经使用。
- 用户真正发送生产消息后才标记“已使用”。
- 已使用素材继续留在管理列表；再次上传由历史校验拦截，状态由本地台账承载，不靠搬动文件夹表达。

## 0.1.6 交互边界

- 浏览器拓展负责 ChatGPT 页面里的界面、拖放和按钮交互。
- 本地工作台负责读取完整目录树、访问本地文件和执行工作包脚本。
- VBS 不属于新版拓展的默认执行链路，只保留为旧流程兼容入口。
- 成品区是文件管理视图，不使用手机分发的“可用作品包”筛选规则。

## 服务对象

服务“生产数字作品”这一段 SOP：减少在文件夹、GPT 会话、提示词和下载工具之间来回切换。

## 界面

- 左侧属于会话资产：完全沿用 ChatGPT 原生侧栏，扩展不接管原生会话。
- 中间属于创作：保持真实 ChatGPT，不绘制假聊天界面。
- 右侧属于本地生产：成品区与素材区上下各占一半，两区都采用可展开的文件管理树，紧凑、可滚动、可拖动。
- 生产舱每次进入 ChatGPT 默认展开；用户临时收起后，独立的小型“创作舱”按钮必须留在页面右侧，不能随面板一起移出屏幕。
- 当前团建素材库与成品库作为首次启动默认数据直接内置；用户无需配置即可看到地址和目录内容。工作台返回的有效路径拥有更高优先级。
- 视觉方向与 ChatGPT 原生灰白工具界面融合：继承网页字体和正文尺度，使用低对比边框、紧凑行高与轻量背景，不使用英文营销抬头、绿色渐变、重阴影、大面积营销卡片或重复统计。

## 边界

扩展、工作台、Skill 和本地打包器分别是独立产品。扩展可调用它们的稳定接口，但不复制它们的数据真源。
