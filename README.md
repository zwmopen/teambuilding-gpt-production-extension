# 团建 GPT 数字作品生产扩展

## 0.2.14 与团建工作台 0.14.2

当前扩展是工作台内置 GPT 的网页执行端。真实 Plus 验收已完成两套闭环：只识别本轮计划、只发送一次 `1`、只下载本轮生成图、等待完整文案后写入 TXT，再交给工作台查重打包。图片不足时直接跳过，不补图、不把用户上传素材当成成品。

工作台负责本地素材树、模板树、队列、账号、额度、成品目录和生产历史；扩展只负责 ChatGPT 网页内部动作。两边不得各维护一套 DOM 自动化。

## 0.2.12 与团建工作台 0.14.0

扩展继续负责 ChatGPT 网页内部的真实上传、阶段识别、提示词、当前回复下载和工作包交付；工作台负责本地素材、模板、账号档案、额度、队列和归档。两边共用一个批次号和一套下载打包能力，不再各写一套容易互相打架的自动化。

- 当前回复下显示“下载本组”“下载并打包”，文案回复旁显示复制和 TXT 下载；
- 生成图片与小红书文案请求可以并行等待；
- 图片不足或文案为空时停止打包；
- 支持工作台传入最低图片数、预期图片数、确认词、文案请求词及真实输出目录；
- 遇到验证码、网页验证或无法识别的页面状态只暂停并提示，不尝试绕过。

这是“生产数字作品”SOP 的专用浏览器扩展，不是团建内容工作台，也不是需要单独安装的油猴脚本。

安装后，真实 ChatGPT 页面形成三个工作区：

1. 左侧：ChatGPT 原生会话列表；扩展不再搬动或接管原生会话节点。
2. 中间：ChatGPT 原生聊天界面。
3. 右侧：上下分区的生产舱。上半区读取成品库，下半区读取素材库；点击或拖动即可把图片与文案放入当前对话。

生产舱在每次打开 ChatGPT 页面时默认展开。点击右上角收起后，页面右侧会始终保留“创作舱”小按钮，可随时重新展开。视觉继承 ChatGPT 的字体、字号和灰白工具语言，保持像网页自身功能，而不是另起一套模拟界面。

扩展通过本机 `127.0.0.1:4327` 与团建内容工作台协作。工作台只提供已授权目录、文件流和去重状态；扩展本身不获得任意磁盘读取权限，也不保存 GPT 或 Google 凭据。

## 团建工作台内置模式

工作台 0.13.0 可在“内容生产（自动）”中直接承载真实 ChatGPT。该模式仍加载本扩展的上传、提示词、下载和工作包能力，但会隐藏扩展自己的右侧生产舱，避免出现两套素材区。

左侧可同时选择多个母版和多个素材文件夹，工作台按“素材数 × 母版数”建立任务。每个母版只建立一个新会话并初始化一次，随后在该会话中串行处理所有选中素材；没有选择母版时，直接沿用当前已经沉淀规则的 GPT 会话。每组包含当前素材图片、TXT/Markdown 与合并后的母版规则。自动流程会等待官网原生附件预览、迁移计划、确认后的新图片和小红书文案，最后下载并交给本地工作包脚本。任一真实阶段未完成，都不会显示为完整成功。

失败任务会保存已经完成的计划、图片、文案和打包检查点。点击重试时从失败阶段继续，避免再次上传附件或重复生成已完成的内容。手动模式只准备当前一套附件与提示词，用户点击“完成当前，上传下一套”后才处理下一套。

每批下载使用独立批次编号，文件名包含批次、序号和总数。本地工作台只打包这一批文件，并复核图片数量和 TXT；下载目录中的旧图不会被带入。账号未登录、平台要求验证、触发限流、生成超时或文案为空时，当前队列会暂停并给出原因。

工作台可以设置生产间隔的随机范围、单帖超时、每轮最大套数、是否自动确认、自动复制文案和自动打包。随机间隔只是正常的队列节奏，不会尝试绕过平台验证或访问限制。

内置模式使用工作台动态注入的本机端口，不写死 4327；正式版、开发版和测试端口可以互不干扰。ChatGPT 登录会话由工作台独立 Chromium 分区保存，扩展不读取、复制或导出 Cookie。

成品区读取设置目录下的完整文件树，不再只显示符合手机分发条件的作品集。“已发送”“发布空间”、刚下载打包的小文件夹、普通文件和大型作品集都会保留，并可逐级展开查看。

上传并不是界面演示：点击“传 GPT”或把帖子文件夹拖入中间聊天区后，扩展会先查询历史去重，再从已授权本地目录读取图片与文案，放入 ChatGPT 的真实附件入口并填入生产指令。底部队列会显示读取数量、成功、重复、失败、取消和重试状态。

上传不会清空输入框里已有的文案；生产指令会追加到现有草稿之后。只有 ChatGPT 原生附件预览真正出现，扩展才会显示上传成功。拖放只在中间聊天区触发，左侧会话和导航不受影响。

文件树里的真实文件夹可以拖到同一素材库或成品库内的另一个文件夹。扩展会先显示来源与目标并要求确认，本地工作台只允许移动真实目录，拒绝根目录、文件、软链接、跨库移动、移入自身子目录和同名覆盖。

素材进入附件区后会自动记为“已加入 GPT”；当这条生产消息真正发送后，工作台自动把它登记为“已使用”。已使用素材仍保留在侧栏供筛选、改标签和管理；再次上传时会被历史校验拦截。原文件夹保持原位，不通过移动文件来制造状态。

上传前还会计算图片与文案的内容指纹。即使已使用素材后来改名或移动，只要内容没有变化，也会被识别为同一份素材并拦截。

素材文件夹以独有文件夹哈希作为稳定身份；两份内容相同的文件夹也有各自的哈希和标签。每个文件夹只显示一个母标签：`团建游戏`、`团建转化` 或 `合集攻略`；“聚会游戏”“破冰游戏”等同义名称会统一归到“团建游戏”。母标签可人工修改，人工选择优先于自动识别，并在同卷改名或移动后继续保留。

素材区可按母标签、季节、节日和使用次数组合筛选，也可搜索名称、标签或哈希。“季节”和“节日”采用可展开分组，下面只显示实际有素材的小标签；地区不单独占用筛选区，统一归入“团建转化”母标签。每个文件夹提供可配置快捷按钮，用于切换母标签、把使用次数加一，或移动到预设目录；齿轮设置可控制按钮是否显示和按钮名称。

筛选读取本地工作台生成的全库索引，不要求先逐个展开分类。使用次数会自动合并既有“素材链接记录”、制作日志和扩展后续实时记录；能唯一对应当前素材文件夹的历史记录自动回填，不能唯一确认的只进入待核对，不要求用户凭记忆补录。

ChatGPT 页面与本地端口之间的请求由扩展后台桥接，避免 HTTPS 页面受浏览器私有网络策略影响。下载按钮会等待浏览器确认文件真正落盘后再显示完成，并把完成事件交给本地工作台记录。“打包作品”默认走“拓展 → 本地工作台 → PowerShell 工作包脚本”，不再调用 VBS；旧 VBS 仅作为独立兼容资产保留。

发布验收不使用模拟聊天框代替真实效果。只有附件出现在 ChatGPT 官网原生会话、生成结果真实存在、文件真实写入下载目录且本地台账有完成记录，才算链路通过。

首次打开不需要填写路径。扩展已内置当前使用中的默认目录：

- 成品区：`D:\AICode\项目推进\projects\江湖有旅人\主项目\成品库（GPT+本地脚本制作）`
- 素材区：`D:\AICode\项目推进\projects\江湖有旅人\主项目\01-素材库`

工作台连接后会把当前有效目录同步到扩展本地数据；以后在工作台或扩展中切换目录，新的目录会覆盖默认值。

插件会自动连接本地工作台：如果浏览器先打开、工作台后启动，插件会在后台自动重试。首次连接只读取顶层素材分类；展开哪个分类才扫描哪个目录，不再等待整个素材库。

## 安装

1. 先启动“团建内容工作台”。
2. 在 Edge 扩展管理页开启开发人员模式。
3. 选择“加载解压缩的扩展”，指向 `src`。
4. 打开或刷新 `https://chatgpt.com/`。

浏览器首次安装需要本人确认一次“加载解压缩的扩展”，这是浏览器的安全边界。安装后不需要再次安装油猴；Google 与 ChatGPT 登录仍由日常浏览器账号环境管理。

## 数据位置

- 素材、成品和生产历史仍保存在原有本地目录。
- 扩展设置保存在浏览器扩展存储中，只记录路径、筛选按钮配置和界面偏好。
- 文件夹哈希、人工母标签和使用次数保存在本地工作台运行数据中，不写入素材文件夹，也不改名素材。
- 工作台提供本机文件接口，不会把素材和历史库上传到第三方。
- 浏览器登录、Cookie、密码和验证码不进入扩展项目或工作台运行日志。

## 去重边界

- 生产去重：读取既有作品历史库，整组图片 SHA-256 判断确定重复，64 位 dHash 只做视觉近似预警。
- 分发防重：手机组与公众号组由工作台台账独立记录。
- 扩展不复制、迁移或改写用户的历史数据库。

## 更新与卸载

- 更新：`src` 是固定源码目录；代码更新后，在扩展管理页点击一次“重新加载”，再刷新 ChatGPT 页面。
- 卸载：在扩展管理页删除本扩展；本地素材、成品、生产历史和工作台数据不会被删除。
- 回滚：重新加载上一版本的发布包目录即可。
